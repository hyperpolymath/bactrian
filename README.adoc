Bactrian is a planned verification suite for a deliberately restricted, pure
subset of OCaml, for BEAM-style actor protocols, and for Idris2 and Zig foreign
function boundaries. It aims to route proof obligations to Why3 with SMT
solvers, to Apalache, and to checked proof receipts. The design is a research
proposal.

[IMPORTANT]
====
*Status: research stage.*

* Bactrian has no proof engine.
* The repository contains no OCaml code, no Dune project and no Why3 file.
* The only executable is a readiness preflight. It cannot establish a proof.
* No verification result exists. Do not read any file here as a proof.
* Files under `verification/proofs/` and `src/interface/` are scaffold from the
  repository template. They are not Bactrian proofs.
====

== What exists today

* `docs/architecture/BACTRIAN-VERIFICATION-SPEC.adoc`: the architecture and
  soundness contract.
* `docs/architecture/BACTRIAN-IMPLEMENTATION-PLAN.adoc`: the milestones 0 to 6.
* `docs/status/BACTRIAN-ULTRAPLAN.adoc`: work packages WP-00A to WP-09 and
  gates G0 to G5.
* `scripts/bactrian/doctor.sh`: the readiness preflight. It checks required
  tools, the ECHIDNA adapter setting, the authority lock and the planned source
  files.
* `tests/bactrian/doctor_test.sh`: the test of the preflight.
* `.machine_readable/bactrian/authorities.lock`: eight upstream authority rows.
  All eight are `UNPINNED`.

== Run the preflight

[source,bash]
----
bash scripts/bactrian/doctor.sh
bash tests/bactrian/doctor_test.sh
----

`doctor.sh` prints one line per check. It exits with status 2 and prints
"Preflight BLOCKED" while tools or authorities are missing. This is the
expected result today. A green exit would still not mean that anything is
proved.

`doctor_test.sh` tests the preflight itself. It uses synthetic fixtures. A pass
means the preflight behaves as designed. It says nothing about Bactrian proofs.

CI runs both commands in `.github/workflows/bactrian.yml`.

== Planned layers

* *Layer A:* a sequential, pure OCaml subset. The plan uses Why3 and SMT
  solvers, with strict Dedukti witnesses.
* *Layer B:* actor, mailbox and protocol models. The plan uses K-CUT artifacts
  from `choreographic-types` and Apalache bounded model checking.
* *Layer C:* a verified foreign boundary. The plan uses an Idris2 ABI manifest
  and a Zig implementation checked by Idris2 QTT and ZigProve.

None of these layers is implemented.

== Working in this repository

The repository was created from the Rhodium Standard Repository template and
keeps its tooling. The Justfile provides these recipes, among others:

[source,bash]
----
mise trust && mise install   # install the pinned developer tools
mise exec -- just doctor     # check the developer environment
mise exec -- just validate   # run the template validation suite
----

Template recipes such as `just readiness` are not yet wired to Bactrian. The
repository map is generated at
link:docs/architecture/REPOSITORY-MAP.adoc[docs/architecture/REPOSITORY-MAP.adoc].
Contributors should read link:CONTRIBUTING.adoc[CONTRIBUTING.adoc] and
link:CODE_OF_CONDUCT.adoc[CODE_OF_CONDUCT.adoc]. Report security issues as
described in link:.github/SECURITY.md[.github/SECURITY.md].
